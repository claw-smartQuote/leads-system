# 上下文管理系統

## 核心原則

**質量 > 速度 > 長度**

1. 保持回复精煉、準確、有價值
2. 避免冗長的解釋和重複信息
3. 定期壓縮和整理對話歷史
4. 優先使用本地工具和腳本而非冗長推理

---

## 上下文壓縮策略

### 1. 自動壓縮觸發條件

當會話達到以下條件時自動壓縮：
- 消息數量 > 20 條
- 估計 token 數 > 8000
- 用戶明確要求 /compact

### 2. 壓縮方法

```bash
# 手動壓縮會話
openclaw agent --message "請壓縮我們的對話" --compact

# 或使用 /compact 命令（如果在支持的平台上）
/compact
```

### 3. 壓縮內容保留規則

保留：
- ✅ 重要決策和結論
- ✅ 已確認的事實和數據
- ✅ 用戶明確要求記住的事項
- ✅ 未完成的事項和待辦

丟棄：
- ❌ 中間推理過程
- ❌ 試錯步驟
- ❌ 閒聊和寒暄
- ❌ 已過時的臨時信息

## 回复優化規則

### 1. 開門見山

- **直接回答**問題，然後補充細節
- 避免「好的，我來幫你...」等鋪墊
- 第一個句子就提供價值

### 2. 結構化輸出

使用簡潔格式：
```
【一句話總結】

詳細內容：
- 要點1
- 要點2

下一步：
1. 行動1
2. 行動2
```

### 3. 避免冗餘

- 不重複用戶已經知道的信息
- 不過度解釋工具調用過程
- 簡潔描述操作結果

### 4. 工具調用優化

- 批量執行相似工具（如多個文件讀取）
- 避免不必要的確認提問
- 使用並行調用提高效率

## 會話狀態監控

### 檢查當前上下文大小

```bash
# 查看當前會話狀態
openclaw status

# 查看 token 使用情況
openclaw agent --status
```

### 清理策略

當會話過長時：
1. 主動建議壓縮：「對話較長，建議壓縮上下文以提高效率」
2. 使用 /compact 或 --compact 選項
3. 必要時 /reset 開始新會話（保留記憶文件）

---

## 最佳實踐

### 對於用戶請求

| 情況 | 策略 |
|------|------|
| 簡單問題 | 直接回答，1-2句話 |
| 複雜任務 | 給出執行摘要 + 關鍵結果 |
| 多步驟操作 | 顯示進度，最終給出總結 |
| 錯誤/問題 | 簡潔說明原因 + 解決方案 |

### 對於工具使用

- 優先使用專用技能而非通用推理
- 腳本化重複任務
- 本地執行 > 遠程調用

### 對於記憶管理

- 重要信息立即寫入文件
- 不要依賴上下文記住細節
- 定期整理 memory/*.md 文件

---

## 應急措施

### 上下文溢出跡象

- 回复速度明顯變慢
- 模型開始重複或遺忘
- 出現無關的輸出

### 立即處理

1. **輕度溢出**：執行 /compact
2. **中度溢出**：總結當前進度，建議新會話
3. **嚴重溢出**：/reset 並從記憶文件恢復上下文
